# Current Repository Cleanup — AI-Reference and Attribution Policy

**Author:** Nasser

## Policy

This platform contains **no artificial intelligence functionality of
any kind** — no AI library, SDK, service, API, model, chatbot,
embedding, inference, or generative component anywhere in the
application. Platform-owned files carry neutral, professional
authorship metadata (**Author: Nasser**) rather than any reference to
an automated development tool.

## Scope of the cleanup

The cleanup covers the **current tracked-file tree only, in both
repositories** (`backend`, `frontend`), as of this phase. It does
**not** rewrite Git history: no `git filter-repo`/`filter-branch`/BFG,
no force-push of rewritten history, no change to any historical commit
message, author, committer, branch, or tag, and no requirement for any
developer to re-clone. Every commit made **during** this phase uses a
professional, neutral message with truthful human attribution and
contains no reference to an automated development assistant.

## What was scanned

A case-insensitive `git grep` across every currently tracked file
(never `.git` history) for: `claude`, `anthropic`, `chatgpt`,
`openai`, `gpt`, `copilot`, `gemini`, `llm`, "language model",
"generative ai", "ai-generated", "vibe coding", and the Arabic
equivalents الذكاء الاصطناعي، تم إنشاؤه بواسطة، نموذج لغوي، مساعد ذكي.

## Findings and disposition

**Backend** — 3 confirmed matches, all reviewed and left unchanged
(false positives, never edited):

1. `composer.lock` — `laravel/agent-detector`'s own package keyword
   metadata: `"claude"` appears because that real, independently
   published Composer package's *stated purpose* is "Detect if code
   is running in an AI agent or automated development environment."
   The word is the package's own description of what it detects, not
   an attribution of who built this platform. Third-party package
   metadata is never edited.
2. `database/seeders/data/qiyas_standards.json` — official Saudi
   government regulatory standards text (imported verbatim from the
   published Qiyas compliance standard), naming the Saudi Authority
   for Data and Artificial Intelligence (SDAIA) and referencing
   government AI-technology-adoption policy requirements. Legitimate
   regulatory subject matter that this platform tracks compliance
   against — altering it would misrepresent an official standard.
3. `docs/qiyas-known-issues.md` — "No AI-generated recommendations."
   A documented platform-scope disclosure (a limitation statement:
   this platform does not produce AI-generated recommendations), not
   an attribution claim.

**Frontend** — **zero matches.**

No genuine attribution reference (a real "built with Claude"/"AI
generated" style comment) was found in either repository's current
tracked-file tree.

## Deterministic CI enforcement

`scripts/scan-prohibited-references.sh` runs the same scan and exits
non-zero if any match is found that isn't on the script's own narrow,
hash-pinned allowlist.

> It ran automatically on every push and pull request until the GitHub
> Actions pipeline was retired. The check is unchanged, but it is now
> **invoked manually** — nothing fails a build on your behalf. The frontend
> copy was removed entirely, as the workflow was its only caller there.

Each allowlist entry:

- Is pinned to a specific file, line number, **and** a SHA-256 hash of
  that exact line's content — never a filename or directory wildcard.
- If the pinned line's content ever changes for any reason, the hash
  stops matching and the scan re-flags it for re-review; an exclusion
  can never silently widen to cover new content.
- Carries an inline comment recording the justification.

The 3 confirmed backend false positives above are the only non-empty
entries (plus the scan script's own necessary self-documentation,
which inherently spells out the trigger words it searches for — also
hash-pinned and documented). The frontend script's allowlist is empty
except for the same self-documentation entries.
